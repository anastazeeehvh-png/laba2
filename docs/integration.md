# Интеграция модулей: система учёта студентов (вариант 5)

## 1. Архитектура взаимодействия

Система состоит из трёх модулей. Модуль обработки работает как сервер REST API, модули ввода и отчёта — его клиенты. Общий транспортный слой `integration_common.py` используется обоими клиентами.

| Модуль | Файл | Назначение |
|---|---|---|
| Модуль ввода данных | `src/student_input.py` | ввод ФИО, группы и среднего балла, маппинг формы в JSON, отправка в API |
| Модуль обработки | `src/student_processing.py`, `src/api_server.py` | проверка данных, хранение, сортировка по среднему баллу, REST API |
| Модуль отчёта | `src/student_report.py` | запрос отсортированного списка, маппинг JSON в строки таблицы, вывод ведомости |
| Транспортный слой | `src/integration_common.py` | HTTP-запросы, разбор JSON, единая обработка ошибок взаимодействия |
| Точка входа | `src/main.py` | команды `serve`, `add`, `report`, `demo` |

Стратегия интеграции — **риск-ориентированная**: первым интегрирован наиболее сложный и рискованный модуль (обработка с REST API и проверкой данных), затем модуль ввода, затем модуль отчёта.

## 2. Схема потоков данных

```
 Пользователь                                                       Пользователь
      │ ФИО, группа, балл (строки)                                       ▲ ведомость (текст)
      ▼                                                                  │
┌───────────────┐   POST /students (JSON)   ┌────────────────────┐   GET /students/sorted (JSON)   ┌───────────────┐
│ Модуль ввода  │ ────────────────────────► │  Модуль обработки  │ ◄────────────────────────────── │ Модуль отчёта │
│ student_input │ ◄──────────────────────── │  REST API + модель │ ───────────────────────────────►│ student_report│
└───────────────┘   201 Created / 400 Error └────────────────────┘      200 OK, список студентов     └───────────────┘
```

## 3. Протокол и форматы

- Транспорт: REST API поверх HTTP/1.1, по умолчанию `http://127.0.0.1:8000`.
- Формат сообщений: JSON, кодировка UTF-8, заголовок `Content-Type: application/json; charset=utf-8`.
- Ошибки возвращаются в виде `{"error": "текст"}` с кодом 400 (некорректные данные) или 404 (ресурс не найден).

| Метод | Ресурс | Назначение | Успех | Ошибки |
|---|---|---|---|---|
| POST | `/students` | добавить студента | 201 | 400, 404 |
| GET | `/students` | список в порядке добавления | 200 | 404 |
| GET | `/students/sorted` | список по убыванию среднего балла | 200 | 404 |
| DELETE | `/students` | очистить список (служебный) | 200 | 404 |

Структура объекта студента в API:

| Поле | Тип | Обязательное | Ограничения |
|---|---|---|---|
| `last_name` | строка | да | не пусто, до 50 символов |
| `first_name` | строка | да | не пусто, до 50 символов |
| `patronymic` | строка | нет | до 50 символов |
| `group` | строка | да | не пусто, до 50 символов |
| `gpa` | число | да | от 2.0 до 5.0 |

## 4. Сопоставление данных (mapping)

| Модуль ввода (форма) | Тип | → | Модуль обработки (API) | Тип | Преобразование |
|---|---|---|---|---|---|
| `fio` «Иванов Иван Иванович» | строка | → | `last_name`, `first_name`, `patronymic` | строки | разбиение по пробелам; отчество необязательно |
| `group` | строка | → | `group` | строка | удаление пробелов по краям |
| `gpa` «4,5» | строка | → | `gpa` 4.5 | число | замена запятой на точку, приведение к float |

| Модуль обработки (API) | → | Модуль отчёта (строка таблицы) | Преобразование |
|---|---|---|---|
| `last_name` + `first_name` + `patronymic` | → | ФИО | объединение через пробел, пустое отчество пропускается |
| `group` | → | Группа | без изменений |
| `gpa` 4.5 | → | Средний балл «4.50» | формат с двумя знаками после запятой |
| порядковый номер в ответе | → | № | нумерация с 1 |

## 5. Примеры запросов и ответов

Добавление студента:

```
POST /students
Content-Type: application/json; charset=utf-8

{"last_name": "Иванов", "first_name": "Иван", "patronymic": "Иванович", "group": "ИС-21", "gpa": 4.2}
```
```
201 Created
{"id": 1, "last_name": "Иванов", "first_name": "Иван", "patronymic": "Иванович", "group": "ИС-21", "gpa": 4.2}
```

Некорректный средний балл:

```
POST /students
{"last_name": "Иванов", "first_name": "Иван", "patronymic": "", "group": "ИС-21", "gpa": 7}
```
```
400 Bad Request
{"error": "Средний балл должен быть в диапазоне 2.0–5.0"}
```

Получение отсортированного списка:

```
GET /students/sorted
```
```
200 OK
[{"last_name": "Петрова", "first_name": "Анна", "patronymic": "Сергеевна", "group": "ИС-21", "gpa": 4.9},
 {"last_name": "Иванов", "first_name": "Иван", "patronymic": "Иванович", "group": "ИС-21", "gpa": 4.2}]
```

Неизвестный ресурс:

```
GET /unknown
```
```
404 Not Found
{"error": "Ресурс не найден"}
```

## 6. Запуск

```
python src/main.py demo                # полный сценарий в одном процессе
python src/main.py serve --port 8000   # REST API в отдельном окне
python src/main.py add                 # ввод студента (в другом окне)
python src/main.py report              # ведомость (в другом окне)
python -m unittest discover tests      # тесты
```
